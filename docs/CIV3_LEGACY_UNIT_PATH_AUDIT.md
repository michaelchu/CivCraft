# Legacy unit path audit after Conquests roster migration

## Findings

- `src/sim/model/units.rs` declares the 92 campaign `UnitKind` variants and `ALL_NATIVE` in Conquests roster order. `src/sim/unit_catalog.rs` checks roster length and exact 1:1 rule IDs against `data/rulesets/civ3_conquests/units.tsv`. No active `UnitKind::Diplomat`, `Spy`, `Caravan`, `Freight`, or other out-of-roster enum identity remains.
- Targeted `src/` search found no Caravan/Freight production, movement, trade-route, or wonder-shield path. The merchant trade modules (`src/sim/trade*`) have already been removed in the current working tree.
- Espionage/bribery module paths (`src/sim/espionage*`, `src/sim/bribery.rs`, and espionage playtest scenarios) are also removed in the current working tree. The separate city-action design is documented in `docs/CIV3_ESPIONAGE_DIPLOMACY_CITY_ACTIONS_DESIGN.md`.
- `src/client/mod.rs::short_unit_name` still contained the old legacy-name switch for the former mixed catalog (including `Guerilla => "Partisan"`, `Galley => "Trireme"`, and legacy plural labels). Since every current `UnitKind` has a Conquests ID and source-backed `name()`, the switch was dead. It now delegates directly to `kind.name()`, preserving the Conquests rules-table identity in UI.
- Other references to Freeciv in the active source are primarily provenance/comments, map RNG or migration context, not legacy unit identities. No changes were made to those shared systems.
- The former `UnitRole` catalog used Freeciv concepts (`DefendGood`, `DefendOk`, `Ferryboat`, `Hunter`, `FirstBuild`, and several start-unit roles). Those labels are removed from unit metadata. Runtime now reads the source Civ III AI strategy set from every `source_ai_profiles` entry and exposes the named PRTO strategies (Offense, Defense, Artillery, Explore, Army, Cruise Missile, Air Bombard, Air Defense, Naval Power, Air Transport, Naval Transport, Naval Carrier, Terraform, Settle, Leader, Tactical Nuke, ICBM, Naval Missile Transport, Flag, King).
- `DefendGood`/`DefendOk` are not Conquests unit strategies. The installed BIQ's `Flags1[4]` gives distinct Offense (`bit 0`) and Defense (`bit 1`) strategies; source profiles may contain separate linked PRTO rows for one visible unit, such as Rifleman's Offense and Defense entries. The runtime now selects defender candidates with `Defense` and transport candidates with `Naval Transport`; tactical-missile hunter dispatch is explicitly limited to the source Cruise Missile and ICBM strategies. The old FirstBuild production shortcut was removed because no such Civ III strategy exists and the migration metadata never assigned it.

## Shared unit mechanics retained

The catalog still requires shared movement, combat, transport, worker orders, aircraft/fuel, bombardment, upgrades, unit support, and AI target-selection systems. These are generic systems parameterized by the 92 Conquests rules rows; they are not unit identities to remove. `Explorer`/`Scout`, `Guerilla`, `Leader`, and `Army` are actual Conquests roster entries and remain. The existing conquest resistance/partisan behavior is left untouched pending a direct Conquests rules verification; this audit does not classify it as a legacy-only path.

## Evidence and residual risk

- Roster: `src/sim/model/units.rs` (`UnitKind`, `conquests_id`, `ALL_NATIVE`); `src/sim/unit_catalog.rs` (92-row/source-ID alignment assertions); `data/rulesets/civ3_conquests/units.tsv`.
- Removed trade/espionage modules are visible as deletions in the shared working tree; the current roster has no corresponding enum variants. The prior roster reconciliation also lists Caravan/Freight and unit-based Diplomat/Spy among identities to remove.
- Unit AI strategies: `data/rulesets/civ3_conquests/units.tsv::source_ai_profiles` preserves each prototype index, `OtherStrategy` link, and full Flags1 bytes; `src/sim/civ3_unit_rules.rs` unions strategy bits from each linked profile. The adjacent OpenCiv3 parser `../openciv3/QueryCiv3/BiqSections/Prto.cs` names the Flags1 strategy bits and confirms `OtherStrategy` is the parent-prototype link for alternate strategies. The complete installed strategy vocabulary is retained even where simulation behavior is not yet implemented.
- Residual strategy gap: the simulation stores the merged set of strategies for a visible unit, not a separately selected strategy profile on each constructed unit. The source data proves available strategies but not the exact runtime profile assignment in the original executable; profile-specific task assignment remains unresolved. Other AI strategy mechanics also need independent behavior audits before claiming parity.
- Advisor ranking gap: exact city advisor wants, unit/building rankings, bodyguard selections, wonder-city choices, and space-race preference scores are not defined by the unit roster or the manual rules audited here. The corresponding tests now check Conquests unit identities, PRTO strategies, technology/resource prerequisites, source unit classes, Apollo gating, and spaceship part limits directly. Runtime preference scoring remains unresolved; these test changes do not claim or alter Conquests AI scoring parity.
- Residual: the runtime remains a larger Civ2Civ3-derived simulation with shared mechanics awaiting source-by-source migration. This narrow pass does not claim all Freeciv-derived mechanics are Civ III-correct. In particular, the conquest-generated Guerilla/Partisan behavior and government advisor bonuses need explicit manual/BIQ comparison before being accepted as Civ III behavior.

Focused verification: `cargo check --offline` passes; `cargo test --offline sim::unit_catalog::tests::ai_strategies_come_from_prto_profiles_and_merge_alternate_strategy_rows` passes. The full suite was not run in this slice.
