The original audit below did not change generator, simulation, or renderer
behavior. The subsequent forest-art fix is described at the end.
The added ignored diagnostic records generation evidence for future regression

## Confirmed finding

**Original finding (addressed below): plains forests and tundra pines could not
be generated by OpenSimplex.**

In `src/mapgen/terrain.rs:412`, only original grassland cells enter the
`available` pool. Forest patch seeds and expansion require that pool
(`terrain.rs:284`, `terrain.rs:515`); cold fallback forests also come from it.
Patch growth changes terrain identity without changing the underlying base.
Unlike the fractal adapter, OpenSimplex has no later forest presentation-base
adaptation. Its generated forests therefore retain Grassland permanently.

The shared renderer correctly selects plains forests for Plains bases and
pines for Tundra bases (`src/client/tileset.rs:183`), but this generator never
provides either combination. Across 108 maps, all 8,582 forests had Grassland
bases; Plains and Tundra forest counts were both zero. This is structural,
not just a rare seed result.

The existing OpenSimplex test at `src/mapgen.rs:1076` checks that *all feature
types combined* cover four bases. Hills and mountains satisfy it even when
forest-specific coverage is missing. A future fix needs per-feature coverage.

Recommended bounded fix: derive forest presentation bases from the retained
OpenSimplex climate fields, preserving terrain identities, placement, quotas,
RNG consumption, and gameplay values; add separate assertions for grassland,
plains, and cold forests. Expanding the forest growth pool would instead
change map generation and should not be treated as an artwork-only fix.

This corrects the earlier broad statement that OpenSimplex already supplied
all necessary feature biomes. That statement was true for relief, not forests.

Tundra mountains and volcanoes reach the renderer's snow selections. Unlike
the earlier fractal census, this sample includes procedural snowy volcanoes.
For example, seed 42 / Cool / age 3 / 36x48 generates one at native (16,8),
and seed 7 generates one at (18,42). Snowy volcanoes are also visible in the north/south captures
listed below; those independent CLI runs use the custom-map roster described
below rather than claiming per-tile identity with the six-player census. Ordinary and vegetated relief use the shared painter's visible
neighbor context, rather than separate generated terrain identities.

All 15 currently generated terrain identities were observed: Coast, Sea,
Ocean, Desert, FloodPlains, Forest, Grassland, GrasslandShield, Hills, Jungle,
Marsh, Mountains, Plains, Tundra, and Volcano. Jungle and Marsh consistently
had Grassland bases. Water bases matched their water categories. Glacier is a
legacy marker, not a required generated terrain; inland water uses Coast
artwork, so absence of a distinct Lake identity is not a missing sheet.

The shared renderer loads the six land transition atlases, three water
atlases, native feature/relief sheets, and river sheets regardless of generator.
The sprite-selection and terrain-blending fixes on this branch therefore also
apply to OpenSimplex. No second generator-specific rendering implementation
was found.

## Implementation: forest presentation biomes

The owner authorized the recommended bounded fix after reviewing this audit.
OpenSimplex now adapts forest art bases after terrain placement:

- Use Tundra when the existing heat field is below `COLD` (85), or latitude
  is colder than the existing `Temperature::biome_bands` tundra cutoff:
  colatitude below 500 for Cool, 344 for Temperate, or 267 for Warm.
- Otherwise use Plains in the existing dry belt (colatitude 623 through 832,
  with at most 3/2/1 neighboring water tiles for Arid/Normal/Wet).
- Otherwise retain Grassland.

Cold takes precedence over dryness. This is a CivCraft art heuristic, not
an original Civ III algorithm or a new climate simulation. The old heat
threshold alone was insufficient to reach pines in the regression presets;
the already-defined temperature-dependent tundra latitude is also needed.
Forest growth eligibility, terrain identities, quotas, RNG draws, and relief
bases are not changed. The Freeciv fractal presentation adapter is unchanged.
Existing saved bases remain authoritative; this applies to newly generated
OpenSimplex maps only.

The ordinary `opensimplex_forests_reach_all_supported_biome_art` regression
checks all three forest bases across seeds 42/7/99 and the nine climate and
temperature combinations, and preserves grass bases for Jungle and Marsh.

For stronger preservation evidence, the ignored census supports immutable
binary generation snapshots. Before the production change, 108 snapshots were
recorded in `/tmp/civcraft-opensimplex-fix/baseline-states`. Every generated
tile field, starts, map seed, civilization count and post-generation RNG
state is compared byte for byte, normalizing only Forest's art base back to
its pre-fix Grassland value. Recording uses `create_new` and cannot overwrite
an existing baseline. Missing comparison files fail the diagnostic.

```sh
mkdir -p /tmp/opensimplex-before
# Run on the production code before the forest-art fix:
CIVCRAFT_OPENSIMPLEX_BASELINE_DIR=/tmp/opensimplex-before \
CIVCRAFT_OPENSIMPLEX_BASELINE_RECORD=1 \
  cargo test --offline --release --lib opensimplex_tileset_audit -- --ignored --nocapture
# Run after the fix, without the recording variable:
CIVCRAFT_OPENSIMPLEX_BASELINE_DIR=/tmp/opensimplex-before \
  cargo test --offline --release --lib opensimplex_tileset_audit -- --ignored --nocapture
```

### Fix validation

- All 108 release maps passed exact normalized-state comparison against the
  immutable pre-fix snapshots, including starts, resources, rivers, relief
  bases, map seed and final RNG state. Only forest art bases were excluded
  from the comparison. Replay determinism, water/feature validity and clean
  ocean-only edge rows also passed.
- The same 8,582 forests now comprise 5,690 Grassland, 2,186 Plains and 706
  Tundra art bases. Full post-fix rows and baseline verification flags remain
  in the local `after-maps.jsonl` evidence listed below. Generated census
  files are not checked into the repository.
- `cargo test --offline --all-targets`: 1,460 library tests passed, 4 ignored;
  report tests 2/2 and CLI tests 19/19 passed. Existing map goldens passed
  without changes. `cargo test --offline --doc` passed.
- The release desktop executable was rebuilt with desktop audio and inspected
  using the complete Civ III installation. Repeated the 14 OpenSimplex
  captures with the same seed, roster, climate, age, temperature and size as
  the audit captures; no terrain fixtures were substituted. Also inspected
  a labeled north-forest crop, the nine-world contact sheet, a detailed south
  view, and the 1600x900 Small-world view.
- Against the unchanged 0.99 threshold, six OpenSimplex comparisons pass and
  eight fail (failed similarities range from 0.96394653 to 0.98661637). The
  failures are retained as failures, reflecting the changed forest material
  and sprite selections; no baselines were replaced or approved. Complete
  scene checks pass on separate `checked-*` runs of affected scenes, including
  the pole camera and no-black-gap checks. No non-baseline check failed.
- Fractal seed-42 Small-world, north-pole and south-pole controls each compare
  at 1.0 against the earlier branch captures. No fractal changes were needed.
