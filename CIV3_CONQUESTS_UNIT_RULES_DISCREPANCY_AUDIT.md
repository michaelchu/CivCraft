# Conquests unit rules discrepancy audit

## Scope and method

Compared the 92 rows in `data/rulesets/civ3_conquests/units.tsv` with the repository's base-game manual (`civ3_manual.pdf`, Appendix A, printed pp. 201–205), the installed `source/Conquests/conquests.biq`, and `source/Conquests/Text/Civilopedia.txt`. The BIQ is the target authority for Conquests numeric values and availability; the manual is an earlier base-game reference. This checkout contains the compressed BIQ, not the unpacked bytes consumed by `tools/export_civ3_conquests_units.py`, so the hash/prototype provenance can be verified here but the exporter’s binary field offsets were not independently re-decoded in this audit.

## Confirmed data gaps and source conflicts

| Finding | Evidence | Classification |
|---|---|---|
| Chasqui Scout’s terrain-specific movement exemptions are now preserved in editable unit data and applied by both player and AI movement cost calculations. | The Conquests Civilopedia says the Incan Chasqui Scout “ignores movement costs for both hills and mountains” (`source/Conquests/Text/Civilopedia.txt`, `#PRTO_Chasquis_Scout`, line 2493). The BIQ record model exposes `PRTO.IgnoreMovementCost` (`openciv3/QueryCiv3/BiqSections/Prto.cs`, line 208). The exporter writes the 14-byte mask to `ignore_movement_cost_hex`; the Conquests Chasqui records set bytes 5 and 6, corresponding to Hills and Mountains in the Conquests TERR order. `UnitRule` parses the mask, and both `movement.rs` and `pf_actions.rs` apply the per-terrain override. `cargo check --offline` passes; no gameplay test was run for this specific movement rule. | Implemented; runtime behavior verification remains. |
| Raw build-availability masks overlap two unique-unit replacements. | `units.tsv` retains Aztecs in Warrior’s `available_to` and Koreans in Cannon’s. The Conquests Civilopedia says Aztecs build Jaguar Warriors “instead of normal warriors” (`source/Conquests/Text/Civilopedia.txt`, line 8888) and Korean Hwach'a replaces Cannon (`lines 4042–4044, 9403`). The reconciliation README already records these two source-mask exceptions. | Confirmed source-data asymmetry, not a transcription error. Unit selection/production must give the unique replacement precedence so these civilizations do not receive both units. Preserve the raw mask for provenance. |
| The base manual’s numbers differ from the installed Conquests table on several reused unit identities. | Examples from Appendix A: Jaguar Warrior 10 shields vs Conquests TSV 15 (both 1/1/2); Rider 30 and 2/2/2 vs TSV 70 and 4/3/3; Cavalry 60 and 6/2/3 vs TSV 80 and 6/3/3; Infantry 8/12/2 vs TSV 6/10/1; Caravel 3 movement/4 capacity vs TSV 4 movement/3 capacity. | Confirmed edition conflict. Do not “correct” Conquests rows from the vanilla manual; keep Conquests BIQ values as the target and use the manual only where rules did not change. |
| Base-manual civilization traits and Scout availability do not describe Conquests unchanged. | The manual lists Iroquois as Expansionist and Britain as Expansionist and lists five Scout-build civilizations (printed pp. 160–162, 201). The installed Conquests Civilopedia says Iroquois are Agricultural/Commercial (`#RACE_IROQUOIS`, around line 8957), and the current Conquests start profile records the Conquests Expansionist roster instead. | Confirmed edition conflict. Starting Scout grants should follow Conquests civilization traits/start rules, not the earlier manual’s tribe list or the Scout build-availability column. |

## No discrepancy found in audited catalog metadata

- **Roster/provenance:** 92 rows are present (59 standard, 31 unique, 2 wonder-created). Every `source_biq` provenance string contains the SHA-256 of the current `source/Conquests/conquests.biq` (`1bd610ab1420217f7d64a9214b60c0bc7686e4781a0d6e66590171535495609c`) and points to a PRTO record. This verifies that the checked-in rows name this BIQ revision; it does not independently prove the exporter decoded each field correctly.
- **Unique-unit metadata:** the 31 `UNIQUE_UNITS` entries in the exporter match the 31 `category=unique` rows one-for-one for civilization, replacement, and expansion. Each unique row is available to exactly its named civilization and has a nonempty `replaces` value. Conquests Civilopedia examples agree: Jaguar Warrior/Warrior (line 8888), Chasqui Scout/Scout (line 2493), Keshik/Knight (lines 3927–3928), Conquistador/Explorer (lines 3942–3944), Berserk/Longbowman (line 3959), Sipahi/Cavalry (line 3976), Gallic Swordsman/Swordsman (line 3991), Ansar Warrior/Knight (line 4010), and Hwach'a/Cannon (line 4042).
- **Representative manual values that still agree:** Settler (30 shields, 0/0/1), Worker (10, 0/0/1), Warrior (10, 1/1/1), Jaguar Warrior movement/combat (1/1/2), Spearman (20, 1/2/1), Swordsman (30, 3/2/1), and Catapult (20, bombard 4/range 1/rate 1) match the manual’s base-game chart and the corresponding Conquests rows. This is a spot check, not a full independent verification of all 92 numeric rows.

## Follow-up evidence needed

To close the remaining numeric audit, compare every PRTO numeric field and availability mask against the TSV. Keep manual differences labeled by edition. Inspect other BIQ PRTO fields omitted from the table before calling unit rules fully source-backed.
